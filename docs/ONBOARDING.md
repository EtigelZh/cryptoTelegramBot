Как строится процесс работы. Рабочий процесс состоит из 2 недельних спринтов:

**ПЛАНИРОВАНИЕ**:
- Смотрим ROADMAP - заводим лейблы под фичи. Фичи декомпозируем на небольшие задачи. Каждую задачу описываем и оцениваем сколько по времени будем делать, ставим label `BACKLOG`.
- Оцениваем сколько задач можем взять спринт, ставим label `TODO`, сортируем задачи по приоритету, самые важные - сверху

**РАБОТА НАД ЗАДАЧАМИ**:
- Задачи в работу берутся из [gitlab доски](https://gitlab.com/meteora-pro/party/crypto/crypto-investing/-/boards), берем задачи сверху вниз из колонки `TODO`.
- По номеру задачи создаем ветку <номер-описание> из ветки `main` пример: `23-improve-code-indexing`
- Вносим изменения, для заголовков коммитов используем [конвенцию](https://www.conventionalcommits.org/en/v1.0.0/) а так же всегда в конце каждого заголовка коммита пишем номер задачи начиная с `#` пример: `feat(dev-boy-api): rework indexing flow #23`
- Не забываем написать unit тесты
- Смотрим сколько потратили времени по wakatime - фиксируем это в задачу
- После того как задача готова создаем merge request в main - и ставим его на лида
- Если есть какие то замечания исправляем их - добавляем затраченное время в задачу

**ЗАКРЫТИЕ СПРИНТА**:
- В конце спринта демонстрируем изменения сделанные в задачах с лейблом `READY FOR DEMO`
- Закрываем задачи - считаем статистику по задачам
- Проводим ретроспективу
	- Что пошло не по плану в спринте
	- Что было хорошо
	- Какие есть идеи по улучшению процессов

**ЕЖЕДНЕВНЫЙ DIGEST**:
- В конце каждого дня пишем в telegram канал
	- Есть ли какие то блокеры которые мешают работать - если нет, то пишем блокеров нет
	- Прогресс по задачам над которыми сегодня работал
